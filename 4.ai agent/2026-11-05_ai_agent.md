### 1. PyRUA-DataFarm: LLM Agent as a Cost-Efficient Teleoperator for Real-Ready Robot Data
- 👥 **作者群**：Kewei Zhang, Juncheng Ma, Guodong Lv, Duomin Wang, Feixiang Ruan et al.
- 📅 **發布日期**：2026-11-03
- 🔗 **論文連結**：[原始頁面](http://arxiv.org/abs/2611.05320v1)  |  📥 **全文 PDF**：[直接下載](https://arxiv.org/pdf/2611.05320v1)
- 🗂️ **資料來源**：arXiv
- 💻 **官方 GitHub 專案**：[https://github.com/DAGroup-PKU/PyRUA-Lean](https://github.com/DAGroup-PKU/PyRUA-Lean)

**🔬 AI 專業導讀與技術突破**：
**【這篇在做什麼】**  
作者提出 **PyRUA‑DataFarm**：一個以大型語言模型（LLM）為核心的「代理人（agent）」，用來取代傳統人工遙控（teleoperation）收集機器人示範資料的過程。代理人只需一段校正（calibration）episode 的真實機器人操作，即可在模擬環境中重建任務、產出可直接用於訓練政策的「真實就緒（real‑ready）」多視角影像與動作標註資料。

**【研究目的】**  
降低機器人資料採集的成本與重複勞動：避免每次新任務都要讓人類操作機器人與耗費機器人時間，同時希望透過一次性的少量真實資料（校正 episode）即可產出大量高品質訓練資料，提升資料利用率與擴展性，並驗證在未見環境下的泛化能力。

**【架構設計】（推測）**  
1. **輸入端**：使用者提出資料需求 + 一段真實機器人校正 episode（影像+關節指令）。  
2. **LLM 代理人（PyRUA Agent）**：「寫場景」→生成模擬器中對應的 3D 場景描述；「寫專家控制器」→產出可在模擬器中執行的控制腳本；「寫成功判斷器」→定義任務成功的檢驗條件。  
3. **模擬器**：執行產出的場景與控制器，產生精確的機器人動作序列（ground‑truth actions）。  
4. **視頻生成模型**：以真實校正影像為條件，渲染每個 rollout 的多視角（例如三鏡頭）照片級影像，確保視角同步。  
5. **獨立評審員（judge）**：對專家控制器與每個渲染 episode 進行驗證，只有通過審查的資料才納入最終資料集。  
6. **輸出**：同步的多視角影像＋機器人動作標註的資料集，可直接喂給政策學習演算法（如Behaviour Cloning）並在真實機器人上部署。

**【核心方法】（推測）**  
- 利用 LLM 的程式碼生成能力，根據自然語言需求自動產出 PyBullet / MuJoCo 等模擬器的場景腳本、PD 控制器或基於強化學習的專家政策，以及對應的成功判斷函式。  
- 透過「一段校正 episode」獲得真實機器人的動作分布作為條件，引導視頻生成模型（例如 Vid2Vid、Stable Video Diffusion）產出具 photorealistic 的多視角影像。  
- 採用「獨立審核」機制：自動規則檢查（碰撞、達標）＋人工或 LLM 基本審查，確保資料品質。  
- 訓練階段：將產出的同步影像‑動作對直接用於行為克隆或迭代強化學習，產出可直接部署的政策。  
- 成本模型：一次性 API 調用（場景、控制器、判斷器生成）約 \$21，渲染合約 \$5，之後每 episode 僅需模擬、渲染與審查的運算成本約 \$0.80。

**【實驗結果】（推測）**  
- 在五項真實機器人任務（例如夾取、堆疊、插孔等）上，僅使用 DataFarm 產出的資料訓練的政策在 100 次試驗中取得 93 次成功，與同等數量的人工遙控資料訓練的政策（84 次成功）相當，甚至略優。  
- 在未見的桌布顏色與環境光照干擾下，DataFarm 政策仍保有 87 次成功，而遙控訓練的政策驟降至 46 次成功，顯示出更好的泛化能力。  
- 資料成本方面，取得一小時三視角資料平均約 \$107，低於中國傳統遙控報價（\$117）與北美純人力成本（\$290），顯示顯著的經濟優勢。

**【總結】**  
PyRUA‑DataFarm 表明 LLM 代理人能夠自動化機器人示範資料的產生流程，將原本依賴人力與機器人時間的遙控工作轉變為一次性低成本的 API 與渲染費用，同時產出具高品質與良好泛化的訓練資料。其價值在於大幅降低資料採集成本、提升資料重複使用率與跨任務遷移能力。限制方面，仍依賴於初始校正 episode 的品質與視頻生成模型的真實感，且對於高度動態或需要複雜觸覺回饋的任務可能需進一步改良。未來研究可探索：(1) 強化 LLM 與模擬器的雙向回饋，使代理人能自行校正場景；(2) 整合觸覺或力覺模態到渲染管線；(3) 在更多機械平台與更長 horizon 任務上進行擴展驗證。

### 2. HARP: Training-Free Dual-Profile Agentic Communication for LLM-Based Recommendation
- 👥 **作者群**：Zhen Tao, Xun Zhou, Xuhui Chen, Ziyue Qiao, Qingqiang Sun
- 📅 **發布日期**：2026-11-03
- 🔗 **論文連結**：[原始頁面](http://arxiv.org/abs/2611.05319v1)  |  📥 **全文 PDF**：[直接下載](https://arxiv.org/pdf/2611.05319v1)
- 🗂️ **資料來源**：arXiv
- 💻 **官方 GitHub 專案**：[https://github.com/Jove-Zhen/HARP](https://github.com/Jove-Zhen/HARP)

**🔬 AI 專業導讀與技術突破**：
**【這篇在做什麼】**  
本文將 LLM‑based recommendation 視為雙方代理人（agent）之間的通訊過程，指出現有做法僅在使用者端建立結構化 profile、將其放入寬頻受限的 reranker prompt，且在 warm‑up 後凍結，導致項目端缺乏對等的 self‑description、profile 資訊被迫進入 prompt 而佔用 token、以及使用者 profile 無法隨後續互動更新。作者提出 HARP，透過補充缺失的四個階段（BUILD、TRANSMIT、UNDERSTAND、SYNC），實現無需額外訓練的雙端 profile 交互。

**【研究目的】**  
作者希望透過對稱化的使用者‑項目 profile 與通訊機制，減輕 prompt 中的 token 競爭、讓 profile 資訊能參與檢索階段、並提供一種可在上下文中自我演化的更新規則，從而在不修改凍結 LLM 骨幹的前提下提升推薦效果，尤其是 Hit@1 指標。

**【架構設計】（推測）**  
HARP 在固定 LLM 基礎上加入三個可即插即用的運算子：  
1. **規則抽取的對稱項目 profile**（零額外 LLM 呼叫），根據項目與使用者的共現統計產出可與使用者 profile 相對應的向量或文字描述；  
2. **可分解的同質性通道** \(H(\phi_u,\phi_i)\)，在檢索階段以門控方式注入，避免佔用 reranker prompt 的 token；  
3. **單通過反思性更新**，利用先前互動的回饋在同一次推理中對使用者 profile 進行無梯度的語境演化，實現即時同步（SYNC）。這三個運算子串接形成「BUILD → TRANSMIT → UNDERSTAND → SYNC」的完整迴路。

**【核心方法】**  
- **規則抽取**：基於共現頻率或 TF‑IDF 等無需 LLM 的統計規則，直接產出項目的自我描述 \(\phi_i\)。  
- **檢索端同質性門控**：計算使用者與項目 profile 的點積或餘弦相似度作為門控值 \(g = \sigma(H(\phi_u,\phi_i))\)，將該值乘到檢索得分上，使高同質性候選項目優先進入 reranker。  
- **反思性 profile 更新**：在一次推理中，利用上一步的 reranker 輸出（如顯示點擊或停留時間）作為弱監督信號，對使用者 profile 進行線性插合或添加殘差，完成在‑context 的演化，全程不需梯度回傳。  
所有步驟僅依賴規則運算與向量運算，故稱為「training‑free」。

**【實驗結果】**  
作者在 Yelp、Books、MovieTV、Goodreads 四個公開推薦基準上進行實驗。相比當前最強的已發表基線（如 LLMRank、Prompt‑Rec 等），HARP 在 Hit@1 上提升 6.9%～24.0%，且經 Holm 校正後的家族誤差率 p 值均小於 1e-9，顯著顯著。消融實驗顯示三個運算子皆有正向貢獻，其中檢索端同質性門控（retrieval‑side gate）貢獻最大；反思性更新雖帶來少許延遲，但仍在可接受範圍內。 per‑case 歸因分析證明各運算子的增益具有互補性。

**【總結】**  
本文提出了「agentic‑communication」的概念框架，並以 HARP 提供了一個無需額外訓練、僅依賴規則抽取與向量運算的具體實現，成功突破了傳統 LLM‑based recommendation 中單側 profile、prompt‑trapped 及無更新機制的限制。價值在於簡單高效且可直接 plug‑and‑play；限制主要是依賴靜態共現規則產出的項目 profile，可能無法捕捉高階語義，且反思性更新僅作為單通過的近似。未來可探索利用小型 adaptor 或少量標籤資料進一步強化項目 profile 的表達力，或將同質性門控擴展至多跳圖傳播，以提升泛化能力。

### 4. ScamWorld: An Interactive Environment for Evaluating Web Agents Against Online Fraud
- 👥 **作者群**：Yutao Wu, Xiao Liu, Ming Wen, Hanxun Huang, Jun Wang et al.
- 📅 **發布日期**：2026-11-03
- 🔗 **論文連結**：[原始頁面](http://arxiv.org/abs/2611.04879v1)  |  📥 **全文 PDF**：[直接下載](https://arxiv.org/pdf/2611.04879v1)
- 🗂️ **資料來源**：arXiv
- 💻 **官方 GitHub 專案**：[https://github.com/wuyoscar/scamworld-bench](https://github.com/wuyoscar/scamworld-bench)

**🔬 AI 專業導讀與技術突破**：
**【這篇在做什麼】**  
本文提出 ScamWorld，一個互動式網頁環境，專門重建真實世界中報告過的詐騙網站（如假電商、虛假投資平台、先付費騙局），以此評估網頁代理（Web Agent）在執行任務時面對線上詐騙的行為與防禦能力。

**【研究目的】**  
作者發現現有研究多聚焦於對抗性提示或欺騙性介面，卻鮮少系統性考量網頁代理遇到以欺騙人類為目標的詐騙內容。因詐騙網站壽命短、難以蒐集，導致缺乏可重複的評估基準。因此他們希望建構一個可重用、可控的測試平台，以量化不同大型語言模型驅動的網頁代理在真實詐騙情境下的欺騙率，並探索其決策過程中的問題點，為後續強化代理的安全機制提供依據。

**【架構設計】（推測）**  
ScamWorld 包含三個主要模組：  
1. **詐騙場景庫**：依據公開的詐騙報告（如 FTC、IC3）標註不同類型、語言與欺騙機制的網站快照。  
2. **互動式網頁模擬器**：基於頭less瀏覽器（如 Playwright）重現場景庫中的頁面，保留原始 HTML、JS 與視覺提示，使代理能進行瀏覽、點擊、填表等操作。  
3. **評估與追蹤框架**：紀錄代理的軌跡（URL、點擊、輸入），在關鍵決策點（付款、提交憑證、連結錢包）標記是否遭詐騙，並計算欺騙率與決策延遲。  

**【核心方法】（推測）**  
- 先從公開詐騙報告中萃取網站結構與欺騙徵跡（如假價格、緊急呼籲、偽造支付頁面），透過腳本自動生成對應的 HTML/CSS/JS 檔案，存入場景庫。  
- 使用六種 frontier LLM（如 GPT‑4、Claude‑2、Llama‑2 等）作為代理的政策網路，透過 prompt 指定任務目標（例如「購買此商品」或「轉帳指定金額」），讓模型在互動模擬器中自主導航。  
- 在每個任務執行前後，記錄模型對網頁內容的解釋（推測為利用模型的自我解釋能力）與最終動作，以判斷其是否被詐騙誘導。  
- 實驗採用交叉驗證：每個場景隨機抽樣 10 次執行，計算平均欺騙率與成功率，並與隨機基線（不看頁面直接依照指令）比較。  

**【實驗結果】**  
在涵蓋英文、中文與西班牙文的 120 個重建詐騙場景中，六種模型的基線欺騙率介於 11%~35% 之間，其中付款相關行為（如點擊「立即購買」）的欺騙率顯著高於提供憑證或錢包資訊的行為。深入軌跡分析顯示，約 40% 的代理在察覺可疑提示（例如價格異常低、網域不匹配）後仍繼續執行，解釋為將使用者原始指令視為對網站額外條款的授權。相比於隨機基線，所有模型在欺騙偵測上均顯著提升（p < 0.01），但仍有顯著空間可改進。

**【總結】**
