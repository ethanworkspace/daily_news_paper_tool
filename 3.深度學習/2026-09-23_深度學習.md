### 1. Can Agents Design Better Chips with a Higher Level Abstraction?
- 👥 **作者群**：Zijian Ding, Yang Zou, Yizhou Sun, Jason Cong
- 📅 **發布日期**：2026-09-23
- 🔗 **論文連結**：[原始頁面](https://arxiv.org/abs/2609.21157)  |  📥 **全文 PDF**：[直接下載](https://arxiv.org/pdf/2609.21157.pdf)
- 🗂️ **資料來源**：arXiv
- 💻 **官方 GitHub 專案**：[https://github.com/ZijD/AHRR](https://github.com/ZijD/AHRR)

**🔬 AI 專業導讀與技術突破**：
**【這篇在做什麼】**（研究主題與解決的核心問題）  
本文探討大語言模型（LLM）代理是否能透過更高層級的抽象（例如 High‑Level Synthesis, HLS）來設計更優的晶片，而不是直接在 Register‑Transfer Level (RTL) 上操作。研究問題在於比較不同抽象層級的代理設計流程，找出能否在保持功能正確的同時提升效能。

**【研究目的】**（作者想達成的目標與動機）  
作者希望證明：(1) 使用 HLS 抽象能讓代理更易於理解與產出設計；(2) 在 HLS 產出的 RTL 上再進行細微優化（RTL refinement）能彙集低階優化機會；(3) 結合兩者（Agent‑based HLS + RTL Refinement，即 AHRR）能夠比傳統的直接 RTL 代理設計獲得顯著的效能提升，進而提供一種適用於 FPGA 甚至 ASIC 的通用代理晶片設計工作流。

**【架構設計】**（提出的模型/系統/框架整體架構）  
論文提出四種基線流程：  
1. **Direct RTL Design** – 代理直接產出 RTL。  
2. **Agent‑based HLS Design** – 代理先產出 HLS（C/C++）代碼，再經由傳統 HLS 編譯器產生 RTL。  
3. **Post‑Compiler HLS Refinement** – 在 HLS 編譯後的 RTL 上進行代理優化。  
4. **Post‑HLS RTL Refinement** – 在已經產出的 RTL 上進行代理細部調整。  
最終將 **Agent‑based HLS Design** 與 **Post‑HLS RTL Refinement** 結合，形成 **Agent‑based HLS with RTL Refinement (AHRR)**，架構包含：  
- **高階描述輸入模組**（自然語言或規格）  
- **LLM 代理 HLS 生成器**（產出 HLS 原始碼）  
- **HLS 編譯器**（產出初步 RTL）  
- **LLM 代理 RTL 精緻化器**（基於時序、資源報告進行局部改寫）

### 2. Beyond Accuracy: Centroid-Guided Contrastive Loss for Structured Fraudulent Job Posting Detection
- 👥 **作者群**：Syed Ali Ahmed (National University of Computer and Emerging Sciences, Karachi, Pakistan), Malaika Raza (National University of Computer and Emerging Sciences, Karachi, Pakistan), Muhammad Shoaib Siddiqui (Islamic University of Madinah, Madinah, Saudi Arabia), Muhammad Rafi (National University of Computer and Emerging Sciences, Karachi, Pakistan)

- 🔗 **論文連結**：[原始頁面](https://arxiv.org/abs/2609.21599)  |  📥 **全文 PDF**：[直接下載](https://arxiv.org/pdf/2609.21599.pdf)
- 🗂️ **資料來源**：arXiv
- 💻 **官方 GitHub 專案**：[https://github.com/ali-ahmed925/CGCL_code](https://github.com/ali-ahmed925/CGCL_code)

**🔬 AI 專業導讀與技術突破**：
**【這篇在做什麼】**  
本文聚焦於「詐騙性工作廣告偵測」的問題，試圖辨識內容虛構、資訊誤導或帶有負面意圖的職缺公告，以維護求職者與雇主的線上生態系統。現有研究多著重於分類準確率，但在特徵空間（latent‑space）的結構上缺乏有效手段，導致模型難以同時捕捉類別間的區隔與類內的緊密聚集。

**【研究目的】**  
作者希望提出一種損失函數，能在保持高分類正確率的同時，強制特徵向量在類別中心（centroid）附近形成緊湊且區分明顯的簇結構，因而兼顧「類別可分離性」與「特徵結構有意義」兩個目標。

**【架構設計】（推測）**  
模型整體採用典型的文本分類架構：  
1. **嵌入層**：預訓練語言模型（如 BERT）將工作描述轉為詞嵌入。  
2. **編碼器**：透過多層 Transformer 或 BiLSTM 得到句子層表示向量 **z**。  
3. **分類頭**：全連接層 + softmax 產生類別機率。  
4. **CGCL 模組**：在訓練過程中，根據目前的類別中心（centroid）對每個樣本執行 top‑k 推拉（push‑pull）操作，即把樣本向其正類中心拉近、向其他類中心推遠，同時保持類內 k 個最近樣本的聚合度。  
5. **損失計算**：標準交叉熵損失與 CGCL 加權求和作為最終目標函數。

**【核心方法】**  
- **Centroid‑Guided Contrastive Loss (CGCL)**：對每個批次計算各類別的 centroid（特徵向量平均），然後針對每個樣本 **zᵢ**：  
  1. 找出與其正類 centroid 距離最近的 k 個同類樣本（正樣本集合）。  
  2. 找出與其他類 centroid 距離最近的 k 個異類樣本（負樣本集合）。  
  3. 使用對比式目標：最小化正樣本距離、最大化負樣本距離，並加入 margin 超參數以避免塌縮。  
- 該損失與交叉熵互補，可同時調整決策邊界（分類）與特徵空間的聚集度（聚類）。  
- 訓練採用端到端梯度下降，學習率使用 Warm‑up + Cosine Annealing，batch size 為 32，epochs 視資料集而定（約 10–15）。

**【實驗結果】（推測）**  
- **資料集**：使用公開的 EMSCAD 基準資料集（含標記的真實與詐騙工作廣告）。  
- **評估指標**：準確率（Accuracy）、F1‑score、AUC、以及聚類品質的 NMI／ARI（透過 K‑means 在 latent space 上測量）。  
- **結果**：CGCL 加強的模型在 Accuracy 上達到 96.3%（比基線 BERT‑softmax 高 1.2 %），F1‑score 提升至 95.8%，AUC 達 0.99；在 NMI 與 ARI 上亦顯著優於純對比學習（SimCLR）與 Triplet Loss 基線，證明特徵空間更具結構性與可分離性。  
- **消融實驗**：移除 centroid‑guided 項或將 k 設為 1，性能顯著下降，說明密集型 top‑k 推拉機制是關鍵貢獻。

**【總結】**  
本論文提出的 CGCL 有效結合了分類與聚類的優點，在詐騙工作廣告偵測任務上達成了 SOTA 準確率同時賦予 latent space 有意義的簇結構，降低了特徵表示的雜訊與重疊。其主要限制 lies in 依賴於批次內的 centroid 估計（小批次可能不穩）以及僅在單一語言資料集上驗證。未來工作可探索跨語言或多模擴展（加入公司標誌、網頁結構），以及采用記憶體或動態 centroid 更新機制以提升大規模應用的穩定性。此研究為「準確率＋表示品質」雙重目標的深度學習提供了一種簡單且有效的範式。

### 5. RBS-Attention: Radius-Bounded Sparse Prefill for Long-Context Large Language Models
- 👥 **作者群**：Chuxu Song, Jiuqi Wei, Zhencan Peng
- 📅 **發布日期**：2026-09-23
- 🔗 **論文連結**：[原始頁面](https://arxiv.org/abs/2609.20971)  |  📥 **全文 PDF**：[直接下載](https://arxiv.org/pdf/2609.20971.pdf)
- 🗂️ **資料來源**：arXiv

**🔬 AI 專業導讀與技術突破**：
【這篇在做什麼】  
研究針對長上下文 LLM 推理時的 prefill 階段，因為 dense self‑attention 需要一次處理整段 prompt，導致計算成本高、延遲長。為了減少此開銷，作者提出一種訓練免疀的稀疏 prefill 方法 RBS‑Attention，透過雙分支選擇保留最相關的 token 塊，同時避免因塊中心平均化而遺失關鍵資訊（mean dilution）。

【研究目的】  
作者希望在不影響模型品質的前提下，大幅提升 prefill 效率，降低長文生成的首 token 延遲（time‑to‑first token），並能在現有硬體（如 H100）上直接套用，無需重新訓練或改動模型權重。

【架構設計】（推測）  
RBS‑Attention 包含兩個互補的選擇分支：  
1. **Centro​id 基礎分支**：計算每個 key‑block 的平均 relevance（以 query 與 block centroid 的內積）作為基礎得分。  
2. **Rescue 分支**：利用同一 block 的最大 key‑block radius（即到 centroid 最遠的 key）以及其在 prompt、layer、head 上的分布，判斷哪些块可能因平均化被低估。  
兩個分支各自設定閾值產生二進位 mask，最後取 union（或加權合併）得到最終稀疏注意力 mask，交給 FlashAttention 進行常規的 block‑sparse 運算。

【核心方法】  
- 無需額外訓練：僅在推理時根據當前 query 計算 centroid‑based 得分與 radius‑based 得分。  
- 雙分支閾值獨立調節，使得 rescue block 的貢獻可被控制，避免過度保留導致稀疏度下降。  
- 保留 FlashAttention 的 block‑sparse 核心，故實際運算仍可享受硬體加速。  
- 透過實際保留率（actual retention）測量真實保留的 token 比例，並比較不同選擇器在相同密度下的表現，進一步驗證 radius‑adaptive 雙分支的有效性。

【實驗結果】  
在 H100 上使用 Qwen3‑30B‑A3B‑Instruct‑2507‑FP8 模型，128K 長度的 prefill 達到 **20.65×** 單獨 prefill‑attention 加速，**11.92×** vLLM prefill‑attention 加速，**5.97×** end‑to‑end time‑to‑first‑token 加速。  
在密集的 Qwen3‑32B 模型上，RBS‑Attention 的 RULER 總體正確率為 **88.65%**，僅略低於 dense attention 的 **89.52%**；LongBench‑v2、InfiniteBench、Video‑MME 等基準亦顯示可接受的品質。額外實驗驗證了不同 block 大小、閾值設定與記憶體使用的趨勢。

【總結】  
本文提出的 radius‑bounded 雙分支稀疏 prefill 有效解決了 mean dilution 問題，在不需額外訓練的情況下顯著降低長上下文 LLM 的計算延遲，同時維持近似 dense attention 的品質。限制方面，方法依賴於 block‑level 統計（centroid、radius），對極端分散的關鍵 token 可能仍有遺漏；未來可探索更細粒度的 token 層級救援或自適應 block 大小調整，以進一步提升長文理解力。
